# Esmi VPN administrator dashboard

This release adds an administrator-only Laravel/Filament application to the existing Ubuntu 22.04 installer. Staff manage VPN access manually. Customer sign-in, self-service pages, checkout, payment processing, invoices and revenue screens are excluded.

## Features

- First-owner creation using a random **eight-character** installation key.
- Required authenticator MFA with recovery codes; owner, VPN operator and support roles.
- Existing VPN-account import, add, early extension, suspension/resume, public-IP caps, credential rotation and permanent removal.
- Manual customer/contact records and access-plan templates, including no-expiry access.
- Multiple private node connections, last-sampled service health, resource usage, online public IPs, aggregate traffic and a usage chart.
- Durable queued mutations, root-registry operation IDs, stale-state rejection, failure visibility and retry recovery.
- Internal support records, audit history and in-dashboard health/failure notifications.
- Daily encrypted backups with an isolated verification/restore rehearsal command.

Public-IP slots retain their documented meaning: phones on the same Wi-Fi may share one slot. This release does not add tamper-resistant physical-device binding or automatic Happ Limited Links integration.

## Installation

Fresh installation:

```bash
git clone https://github.com/johntejano2241/vless-reality-install.git
cd vless-reality-install
sudo bash install.sh
```

Existing installation:

```bash
cd ~/vless-reality-install
git pull --ff-only
sudo bash upgrade.sh
```

The full installer/upgrade also calls `install-admin.sh`. It installs Docker/Compose if needed, runs the web application as the dedicated unprivileged `reality-admin` UID, and starts the private root management bridge and encrypted-backup timer. The application does not receive the Docker socket, SSH credentials, server private-key files or a root shell.

For an existing CLI-only deployment that deliberately does not need the dashboard:

```bash
sudo env INSTALL_ADMIN_DASHBOARD=0 bash upgrade.sh
```

To install or update the dashboard after the VPN manager is current:

```bash
sudo bash install-admin.sh
```

Use the complete source release, including `dashboard/composer.lock`. Composer dependencies are pinned and tested in GitHub Actions. The dashboard's containers include PHP 8.4; the Ubuntu host does not need a PHP upgrade. Reserve resources for both the web containers and Xray; capacity must be measured rather than inferred from a customer count.

## First administrator: eight-character setup key

After the dashboard health check succeeds, installation prints a setup URL and an eight-character alphanumeric key **in the server terminal**. The key is not an admin password or a permanent API key.

By default the web app binds only `127.0.0.1:8080`. From your own computer, open a tunnel:

```bash
ssh -L 8080:127.0.0.1:8080 USER@SERVER
```

Open `http://localhost:8080/setup`, enter the printed key, and choose your administrator name, email and password. Sign in at `/admin/login`, then enroll an authenticator and retain its recovery codes privately.

The setup key:

- Has exactly eight random letters/numbers generated by a cryptographically secure source.
- Is stored only as a password hash and expires after 30 minutes.
- Is limited by per-IP request throttling and a persistent global failed-attempt counter; ten wrong attempts invalidate it.
- Is consumed in a database transaction when the first owner is created.
- Cannot be used after setup. The `/setup` endpoint then returns 404.
- Is not recreated by reinstalling/upgrading when an administrator already exists.

Deleting an admin record outside the app does not automatically reopen completed setup. The UI prevents disabling/demoting the last active owner. Additional staff accounts are created by an owner inside the dashboard; there is no public registration.

To rotate an expired/unclaimed setup key from the server console:

```bash
sudo docker compose --env-file /etc/reality-vless-admin/compose.env \
  -f /opt/reality-vless-admin/deploy/compose.yaml exec -T app php artisan admin:setup-key
```

If setup is already complete, this command preserves credentials and reports that setup is closed. Password/MFA recovery is a separate root-console operation:

```bash
sudo docker compose --env-file /etc/reality-vless-admin/compose.env \
  -f /opt/reality-vless-admin/deploy/compose.yaml exec --user 0 app php artisan admin:recover owner@example.com
```

Recovery prompts for a new strong password, invalidates sessions and resets lost MFA. Re-enrollment is required after sign-in; it does not reopen the first-admin setup page.

## Optional HTTPS hostname

The default SSH-tunnel mode avoids publishing an unclaimed admin setup page. For a public admin hostname, place a properly configured HTTPS reverse proxy/access gateway in front of the loopback listener; forward the original Host and set `X-Forwarded-Proto: https`. Set `APP_URL=https://admin.your-domain.example` and `SESSION_SECURE_COOKIE=true` in the root-only `/etc/reality-vless-admin/app.env`, then recreate the containers.

For a first installation you may set `ADMIN_URL` and `ADMIN_PORT`:

```bash
sudo env ADMIN_URL=https://admin.your-domain.example ADMIN_PORT=8080 bash install-admin.sh
```

This sets application/cookie configuration, not a DNS record, certificate or public listener. HTTPS must already be terminated by your reverse proxy. The raw VPN listener and admin web hostname remain separate; an occupied Xray TCP 443 is not reused by this dashboard. Re-running installation preserves the stored URL/port and existing credentials. There is no public Xray administration port.

## Authority, stale jobs and credential handling

The root manager's `clients.json` remains authoritative. Both the CLI and the private agent use its lock and validated/atomic config publishing; the web database holds staff/customer metadata and observed VPN state. It does not independently regenerate Xray configuration.

Every queued VPN mutation carries an operation UUID plus the observed client version. The root registry retains applied-operation receipts, including removal tombstones. Retries cannot extend a period twice, and a request based on old state is rejected after a newer change. Operations are shown as queued/running/succeeded/failed; inspect them instead of treating a submitted form as proof of applied access.

The single worker checks the submitting staff member is still authorized. A scheduled dispatcher recovers interrupted enqueue/worker work after five minutes. Unknown/unavailable node data is marked stale; statistics failures do not display fake zero online usage.

Existing root-level account changes can restart Xray, closing existing streams and briefly reconnecting other accounts on that node. This implementation uses that behavior for enforceable suspension, expiry and rotation; it does not advertise seamless per-user disconnection. Extending suspended access never resumes it automatically. A resume cannot make an expired entitlement active.

Only an owner can reveal a VLESS link after confirming the owner password. Ordinary lists, statistics, job payloads and audit entries contain no UUID/profile/private REALITY key. Customer/contact records are administrative records only and have no account credentials.

## Multiple servers

Each node runs the same native manager and private Unix-socket bridge. Add a root-managed, authenticated SSH/VPN transport outside the web app that exposes the remote socket under `/run/reality-vless-admin/NAME.sock`. The remote SSH identity must be restricted to forwarding the approved socket; do not give the web runtime an SSH key, shell or Docker access. Provision transport with your server operator and verify endpoint identity before registration.

In **Servers**, enter the socket basename `NAME`, server label and region. Refresh status to import that node's existing accounts. Arbitrary HTTP URLs, shell commands and filesystem paths cannot be entered as a node endpoint. The `agent` socket is the local server. Creating a server record does not install or enroll a remote VPS automatically.

## Monitoring and support

The scheduler collects enabled-node status every minute. The UI polls cached data every 15 seconds, marks samples older than three minutes stale, and shows failed operations and expiring accounts. Owners receive database notifications for node refresh failures, unhealthy services/statistics, low disk space and exhausted job retries. These are in-dashboard notifications; external email/SMS/pager delivery requires a separately configured integration.

Traffic counters are aggregate observed bytes and handle repeated polling and Xray counter epochs. They can lose the final sampling interval on a crash and are not exact billable GB or enforced hard quotas. IP slots are distinct from physical-device counts. Support staff can view operational/customer records and edit support records; VPN mutations require an operator/owner, and staff/server/audit management requires an owner.

## Backups and recovery

`reality-vless-admin-backup.timer` creates encrypted backups under `/var/backups/reality-vless-admin/`. They include VPN configuration/registry/metadata, application environment and a consistent SQLite backup. The encryption key is `/etc/reality-vless-admin/backup.key`, root-only and excluded from the archive. Store that key and backup copies securely off-host; automatic off-host upload is not configured by this installer.

Trigger and verify a backup:

```bash
sudo systemctl start reality-vless-admin-backup.service
sudo /usr/bin/python3 /usr/local/lib/reality-vless/admin_agent.py verify-backup \
  /var/backups/reality-vless-admin/REPLACE_WITH_ACTUAL_BACKUP.fernet
```

Verification authenticates/decrypts the archive, rejects unexpected paths/links and oversize content, restores into a private temporary directory, validates the registry and checks SQLite integrity. It never overwrites production.

For production recovery, first rehearse on a disposable server. Stop the web stack, preserve the current state, authenticate the selected backup, restore its matched VPN files plus dashboard database/application environment with the original restrictive ownership, remove stale SQLite WAL/SHM files only while all app processes are stopped, validate the Xray configuration, then restart the VPN, bridge and recreated web containers. Reconcile retained queued operations and current expirations before resuming administration. Keep the prior snapshot for rollback. First-admin setup is not a recovery mechanism.

## Diagnostics

```bash
sudo systemctl status reality-vless-admin-agent reality-vless-admin --no-pager
sudo systemctl status reality-vless-admin-backup.timer --no-pager
sudo journalctl -u reality-vless-admin-agent -n 80 --no-pager
sudo docker compose --env-file /etc/reality-vless-admin/compose.env \
  -f /opt/reality-vless-admin/deploy/compose.yaml ps
sudo docker compose --env-file /etc/reality-vless-admin/compose.env \
  -f /opt/reality-vless-admin/deploy/compose.yaml logs --tail=80 app worker scheduler web
```

Protect diagnostic output; do not upload secrets or private profiles to issues. The setup key is intentionally printed only after a successful installation health check. Production VPS deployment and physical Android acceptance are separate from CI validation.
